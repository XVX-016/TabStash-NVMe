# GitHub Release Checklist

Use this checklist when creating a GitHub release for TabStash NVMe.

## Pre-Release

- [ ] All code changes are committed
- [ ] All tests pass
- [ ] Documentation is up to date
- [ ] Version numbers are updated
- [ ] CHANGELOG.md is updated
- [ ] Release notes are prepared

## Version Tagging

- [ ] Create version tag: `git tag v0.1.0`
- [ ] Push tag: `git push origin v0.1.0`
- [ ] Verify tag exists on GitHub

## Build Artifacts

- [ ] **Native Host Binary (Windows)**
  - [ ] Build: `cd tabstash-native && cargo build --release`
  - [ ] Verify: `tabstash-native/target/release/tabstash-native.exe` exists
  - [ ] Test on clean Windows system

- [ ] **Native Host Binary (Linux)**
  - [ ] Build: `cd tabstash-native && cargo build --release`
  - [ ] Verify: `tabstash-native/target/release/tabstash-native` exists
  - [ ] Test on clean Linux system

- [ ] **Windows Installer**
  - [ ] Update installer script with extension ID (if known)
  - [ ] Package installer (if using MSI/Inno Setup)
  - [ ] Test installer on clean Windows system
  - [ ] Verify manifest installation
  - [ ] Verify binary installation

- [ ] **Linux Installer**
  - [ ] Update installer script with extension ID (if known)
  - [ ] Test installer on clean Linux system
  - [ ] Verify manifest installation
  - [ ] Verify binary installation

## Release Notes

- [ ] **Title**: v0.1.0 - Initial Release
- [ ] **Description**: Use template from `docs/RELEASE_NOTES_TEMPLATE.md`
- [ ] **Features**: List all new features
- [ ] **Installation**: Clear installation instructions
- [ ] **Requirements**: System requirements listed
- [ ] **Known Issues**: Document limitations
- [ ] **Links**: Add relevant links (docs, issues, etc.)

## GitHub Release Creation

1. Go to GitHub repository
2. Click "Releases" → "Draft a new release"
3. **Tag**: Select `v0.1.0` (create if doesn't exist)
4. **Title**: `v0.1.0 - Initial Release`
5. **Description**: Paste release notes
6. **Attach Files**:
   - [ ] Windows installer (if packaged)
   - [ ] Linux installer script
   - [ ] Source code zip (optional, GitHub auto-generates)
7. **Publish**: Click "Publish release"

## Post-Release

- [ ] Verify release is visible on GitHub
- [ ] Test download links
- [ ] Update README with release link (if needed)
- [ ] Announce release (if applicable)
- [ ] Monitor for issues

## Important Notes

### Extension ID Handling

**Before Chrome Web Store Approval:**
- Use placeholder: `EXTENSION_ID_PLACEHOLDER`
- Document that users must update after getting extension ID
- Provide instructions for updating manifest

**After Chrome Web Store Approval:**
- Get extension ID from store dashboard
- Update installer scripts with real extension ID
- Rebuild installers
- Create new release with updated installers
- Update release notes

### Binary Distribution

- **Do NOT** upload extension `.zip` to GitHub releases
- Extension is distributed via Chrome Web Store only
- Only upload native host installers
- Provide clear instructions for extension installation

### Version Compatibility

- Document which extension version works with which native host version
- Add version checking in future releases
- Provide migration instructions if needed

## Release Assets

### Recommended Files

1. **tabstash-installer-windows.exe** (or .msi)
   - Windows installer
   - Includes binary and manifest installation

2. **install-linux.sh**
   - Linux installation script
   - Includes instructions

3. **Source code** (auto-generated by GitHub)
   - Full source code archive
   - For users who want to build from source

### Optional Files

4. **tabstash-native-windows.exe**
   - Standalone binary (if users want manual installation)

5. **tabstash-native-linux**
   - Standalone binary (if users want manual installation)

6. **SHA256 checksums**
   - For security verification
